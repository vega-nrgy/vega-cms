# Local Development Setup

## Why WSL2

Production runs Linux containers on Kubernetes, and OCPP tooling (`mobilityhouse/ocpp`, most simulators) is Linux-first. Develop inside **WSL2 (Ubuntu 24.04)**, not native PowerShell.

Keep the repo inside the WSL filesystem (`~/vega-ccms`), **not** under `/mnt/c/...`. Cross-filesystem access is slow and breaks file watching for `uvicorn --reload`.

## Prerequisites

- WSL2 with Ubuntu 24.04
- Docker Desktop with **WSL integration enabled for the Ubuntu distro** (Settings → Resources → WSL integration)
- [`uv`](https://docs.astral.sh/uv/)
- `psql` client (optional, for inspection)

## First run

```bash
cd ~/vega-ccms

uv sync                                   # install dependencies
cp .env.example .env                      # set DATABASE_URL, REDIS_URL
docker compose up -d                      # Postgres + Redis
uv run alembic upgrade head               # apply migrations
uv run uvicorn app.main:app --reload      # API on :8000
curl localhost:8000/health
```

Adjust `app.main:app` if the entrypoint module differs.

## Tests

```bash
uv run pytest tests/unit
uv run pytest tests/integration           # needs docker compose Postgres running
```

Integration tests run against a real Postgres, including the full Boot → Authorize → Transaction → MeterValues → Stop flow. CI (GitHub Actions) runs lint, typecheck and both suites on every push, with Postgres as a service container.

## Migrations

```bash
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
uv run alembic downgrade -1
```

- Review every autogenerated migration before committing.
- Partitioned tables (`meter_values`, `status_notifications`) are **hand-written** with `op.execute()`. Autogenerate cannot express `PARTITION BY` and must be told to ignore them. See [04 — Data model](../architecture/04-data-model.md#partitioned-tables).
- `alembic/env.py` reads `settings.database_url` from `app/core/config.py` (pydantic-settings, `.env`) and targets `Base.metadata`.

## Connecting a simulated charger

Use Solidstudio [`ocpp-virtual-charge-point`](https://github.com/solidstudiosh/ocpp-virtual-charge-point) for day-to-day debugging. Point it at:

```
ws://localhost:8000/ocpp/<charge-point-id>
```

and select OCPP 1.6 or 2.0.1. Use the SAP `e-mobility-charging-stations-simulator` later for load testing.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `Cannot connect to the Docker daemon ... /var/run/docker.sock` | Docker Desktop's WSL integration is off for this distro. Enable it per distro in Docker Desktop settings and restart Docker Desktop. |
| `alembic init` fails with "directory not empty" | A placeholder `alembic/` folder already exists. Remove it (`rm -rf alembic`) and rerun `alembic init -t async alembic`. |
| `prepared statement "..." does not exist` | Running through PgBouncer in transaction mode with asyncpg statement caching on. Disable the cache (see [02 — Deployment](../architecture/02-deployment.md#connection-pooling)). Not an issue against direct local Postgres. |
| Partition insert error `no partition of relation "meter_values" found for row` | The month's partition was not created. Run the partition maintenance job or migration. |
